## SLIDE 2: THE CHALLENGE (2 minutes)

### Visual
- Current pain points listed
- Statistics showing inefficiencies
- Images representing challenges

### Script

"Let me start by highlighting the challenges we currently face in our post-selection process:

**First**, we're managing candidate data across multiple systems—spreadsheets, emails, and various tools. This creates data silos and makes it difficult to get a complete picture of where each candidate stands.

**Second**, feedback collection is inconsistent. We rely on email chains and manual tracking, which often results in lost information and delayed decisions.

**Third**, offer letter generation is time-consuming. Our HR team manually creates each offer, which is error-prone and delays the hiring process.

**Fourth**, there's no centralized platform for policy acknowledgments, salary definitions, or onboarding coordination. This leads to miscommunication and delays.

**Finally**, we lack visibility into the entire hiring pipeline. Recruiters, HR managers, and interviewers can't easily track progress or collaborate effectively.

The HR Post-Selection Manager solves all of these challenges with a unified, integrated platform."

## SLIDE 4: THE FIVE USER ROLES (3 minutes)

### Visual
- Five role icons/avatars
- Permission matrix table
- Role hierarchy diagram

### Script

"Let me introduce the five user roles we've designed for this system:

**Super Admin** - This is the system administrator with full control. They manage all users, configure system settings, and have access to all modules. The Super Admin can create new users, assign roles, and view system-wide analytics.

**HR Manager** - This role handles post-selection HR processes. HR Managers generate offer letters, define salary structures, upload policies, schedule inductions, and send communications to candidates. They're the orchestrators of the hiring process.

**Recruiter** - Recruiters manage the candidate pipeline. They add candidates, update their status through interview rounds, collect feedback from interviewers, and generate reports. They're the primary point of contact for candidate progression.

**Interviewer** - Interviewers have limited access. They can view candidate profiles and add feedback comments. This role is perfect for team members who participate in interviews but don't need full system access.

**Candidate** - This is an external role for job applicants. Candidates can view their profile, see offer letters, accept or decline offers, acknowledge policies, and receive communications. They interact with the system through a dedicated candidate portal.

Each role has specific permissions and can only access the features relevant to their responsibilities. This ensures data security and maintains a clean, focused interface for each user."

**Feedback Tracking**: View all feedback submitted by different interviewers in one place. See technical ratings, behavioral ratings, and detailed comments.

**Real-Time Updates**: All team members see the same data in real-time. When a recruiter updates a candidate's status, everyone sees it immediately."

## SLIDE 6: KEY FEATURES - FEEDBACK SYSTEM (3 minutes)

### Visual
- Feedback form screenshot
- Rating scale visualization
- Feedback history example

### Script

"Next, let's look at the Feedback System, which is crucial for making hiring decisions.

**Multi-Round Feedback**: The system supports feedback from multiple interview rounds—HR Round and Final Round. Each round can have feedback from different interviewers.

**Structured Feedback**: Interviewers rate candidates on two dimensions:
- Technical Skills (1-5 scale): Assesses technical competency
- Behavioral Skills (1-5 scale): Assesses cultural fit and soft skills

**Detailed Comments**: Beyond ratings, interviewers can add detailed comments about their observations, strengths, and concerns.

**Go/No-Go Decision**: For each feedback submission, the interviewer makes a clear decision—Go (move forward) or No-Go (reject).

**Feedback History**: The system maintains a complete history of all feedback. You can see who submitted feedback, when, and what they said.

**Interviewer Comments**: Interviewers with limited access can add comments to existing feedback without changing the ratings. This allows collaboration without compromising data integrity.

**Feedback Summary**: Recruiters can see a summary of all feedback for a candidate, making it easy to make final hiring decisions."

- Gross Salary: Total earnings
- Total Deductions: Sum of all deductions

**Real-Time Updates**: As you enter values, calculations update in real-time. You can see exactly what the candidate will receive.

## SLIDE 13: SECURITY & ACCESS CONTROL (2 minutes)

### Visual
- Role-based access control diagram
- Permission matrix
- Security features list

### Script

"Security is paramount in an HR system handling sensitive candidate information.

**Role-Based Access Control**: Each user role has specific permissions. Users can only access modules and features relevant to their role.

**Authentication**: Secure login with email and password. JWT tokens ensure secure session management.

**Password Security**: Passwords are encrypted and never stored in plain text. Users can reset forgotten passwords securely.

**Data Encryption**: All sensitive data is encrypted at rest and in transit.

**Audit Trail**: Every action is logged—who did what, when, and from where. This creates accountability and helps with compliance.

**Permission Enforcement**: The system enforces permissions at every level. Users cannot bypass restrictions or access unauthorized data.

**Session Management**: Automatic logout after inactivity. Users must re-authenticate for sensitive operations.

**Compliance**: The system helps maintain compliance with data protection regulations by maintaining detailed audit trails and access logs."
